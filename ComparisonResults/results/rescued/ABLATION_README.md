# `unique_dst_ips` ablation — answers review risk R1

**Question.** The /24 subnet arm scores 11 features; the per-destination arm scores
10. The extra one is `unique_dst_ips`. Is the carpet-bomb recovery an artifact of
that extra feature rather than of the change of monitoring key?

**Answer: no.** Re-running the subnet arm with `unique_dst_ips` removed from the
candidate list — so both arms score the identical 10 features — leaves the
headline unchanged at the shipped threshold.

| arm | event population (SYN) | SYN DR @ theta=4.0 | SYN DR calibrated | aggregate @ theta | FPR uninvolved (cal/theta) |
|---|---:|---:|---:|---:|---:|
| per-destination (10 feats) | **678,911 attack windows** | 15.3% | 12.9% | 14.8% | 22.9 / 45.5 |
| /24 canonical (11 feats) | **28,304 zone-seconds** | **100.0%** | 88.2% | 94.4% | 56.4 / 64.7 |
| /24 ablated (10 feats) | **28,304 zone-seconds** | **100.0%** | 83.0% | 94.3% | 56.4 / 64.7 |

**Quote the denominator with the rate.** The two keys do not score the same events.
15.3% is 15.3% of 678,911 per-destination attack windows; 100.0% is 28,304 of
28,304 zone-seconds. The /24 population is **24x smaller** and is a different
population, so "15.3% -> 100.0%" records a change of denominator as well as of
coverage, and is not the recovery of the same window set. Any downstream text that
prints the pair without both denominators is incomplete.

At theta = 4.0 the ablated and canonical subnet arms are identical on detection and
identical to the decimal on false alarms. Only the calibrated variant moves
(88.2 -> 83.0, -5.2 pp), and 83.0% still dwarfs the per-destination 12.9%.

**The calibrated column is clamped.** Per-key calibration searches theta over
[4.0, 20.0] for the smallest value holding the benign rate at or below a 3% target
(`CALIB_TARGET_FPR`), and returns the upper limit when nothing in range reaches it
(`config.py:87-89`, `pipeline.py:246`). Eight of the ten largest /24 victim subnets
return exactly 20.0, and both /16 subnets do:

```
/24  20, 20, 20, 20, 7, 20, 6, 20, 20, 20      8 of 10 at the ceiling
/16  20, 20                                    2 of 2  at the ceiling
```

So the calibrated cells above are mostly the search ceiling, not a threshold that
met its target: the realized uninvolved rate of 56.4% is 19x the 3% aimed at. The
calibrated-vs-fixed distance is bounded by that clamp and must not be described as
a pure calibration cost, nor its size read as "not a detection ceiling".

**Why the feature exists at one scope and not the other.** The same auto-filter
(`filter_active` against `PRODUCTION_39_FEATURES` + `unique_dst_ips`) runs at both
scopes. At per-destination scope `unique_dst_ips == 1` for every window, so it is
dropped as zero-variance. The feature is *created by the key*, not handed to the
subnet arm. The runner's own source says so at `run_litnet_l1subnet.py:47-52`.

**Provenance.** Generated by `ablate_no_unique_dst_runner.py`, a patched copy of
`experiment/run_litnet_l1subnet.py` with two changes: the candidate list drops
`unique_dst_ips`, and `output_path_for()` is redirected so the canonical artifact
is never written. Both runs use `LITNET_DIR=datasets/LITNET-2020/parts` — the same
truncated export as the canonical run, so the comparison is like-for-like in
vintage. Do not compare these cells against complete-export numbers.
